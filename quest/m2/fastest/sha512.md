# [M] SHA-384 and SHA-512 from the fastest source

## Goal

SHA-384 and SHA-512 (and so HMAC-SHA384, HKDF-SHA384, and Ed25519's hash) run
the fastest source on each backend, preferring a verified one when it is as
fast. Today every backend runs Graviola's, and a verified source beats it on
aarch64 and armv7.

## Plan

SHA-512, criterion medians. Each pair of columns comes from one run. rind
against HACL\* (libcrux-sha2, portable Rust): bench-tmp run 41147916836, and a
local run on the i7-8700. rind against aws-lc-rs: bench run 41141591842 on arm,
41147916836 on the EPYC, and a local run on the i7-8700.

| backend | rind, 16KB | HACL\* ✓, 16KB | rind, 64KB | aws-lc-rs, 64KB |
|---|---|---|---|---|
| aarch64, Neoverse-N2 | 33.9 µs | 27.2 µs | 134.8 µs | 49.5 µs |
| armv7 on the same core | 135.8 µs | 90.0 µs | 539.7 µs | 243.7 µs |
| x86_64, i7-8700 (AVX2) | 29.0 µs | 35.3 µs | 108.0 µs | 86.4 µs |
| x86_64, EPYC 7763 | 31.6 µs | 42.0 µs | 125.8 µs | 121.7 µs |

So on aarch64 and armv7, HACL*'s verified portable code is already 1.25-1.5x
faster than Graviola's, and aws-lc is faster still. On aarch64, aws-lc uses
the SHA-512 instructions (FEAT_SHA512, which rind does not require today),
and [aws-lc-verification](https://github.com/awslabs/aws-lc-verification)
proves its aarch64 SHA-384/512 with and without them, and its x86_64 SHA-384/512
on AVX CPUs. Check which aws-lc routine each proof covers and whether it is the
one that measured fastest; armv7's aws-lc SHA-512 (NEON `sha512-armv4`) is
unverified, so there the choice is aws-lc (⚡) against HACL\* (✓) on speed.

RustCrypto's pure-Rust `sha2` took 359 µs at 64KB on armv7 (bench-tmp run
41151132431), level with HACL\*.

Importing aws-lc's assembly would follow `admin/import-aws-lc-arm`. Using
HACL\* on aarch64 adds libcrux-sha2 to that build, which armv7 already pulls
in through libcrux-ed25519.

[moq-dev/rind#41](https://github.com/moq-dev/rind/pull/41) moved armv7 from
HACL\* to Graviola for SHA-2, measuring SHA-512 1.4x slower under qemu and
accepting it; this hardware run confirms the gap.
